## Acceptance criteria

### Environment contract (GOA-1, HJ-24-5)
- **AC1** One authoritative non-secret env contract (`/etc/project-workbench/pw.env`) is defined in
  the repo, generated by a portable script, and consumed by the dashboard, terminal creation,
  persistence/restore, the host owner unit and the container sidecar. All documented
  path/mode/per-user values are covered.
- **AC2** `pw-tmux-restore` exits **non-zero** when an authoritative path is missing/misconfigured
  (registry, app dir, state dir) instead of exiting 0 having restored nothing. "No manifest" stays
  a legitimate exit 0.
- **AC3** Credential identity resolution stays fail-closed: a session whose owner/credential/stamp
  cannot be resolved is still refused, never restored under the shared login.

### Deploy mode (GOA-5, GOA-3)
- **AC4** Deploy mode is resolved by one shared helper. Explicit `host`/`container` is preserved; an
  unrecognised value, or an unset value with container evidence present, fails safely instead of
  silently selecting host semantics. A plain existing host install (unset, no container evidence)
  keeps working.
- **AC5** `install.sh` is deploy-mode gated: container mode never installs/enables the host owner
  unit or its memory drop-in.

### Host owner readiness + ownership (HJ-24-1, HJ-24-2)
- **AC6** The owner unit does not become ready until the exact default-socket tmux server and
  `_keepalive` session are proven live in the owner's own process/cgroup.
- **AC7** A deterministic **no-manifest cold-start** regression proves a terminal client released by
  the readiness barrier cannot become the server creator, asserted on process/cgroup ownership —
  not unit text. A negative control proves the assertion discriminates.
- **AC8** Host mode fails closed when ownership is absent or foreign: terminal creation refuses.
  Covered by tests for owner start failure, crash before readiness, and a foreign-owned server.
- **AC9** `install.sh` does not claim success when the owner unit fails to start in host mode.

### MemoryHigh (HJ-24-3)
- **AC10** The `MemoryHigh` byte calculation is 64-bit safe on `mawk`; executable tests assert exact
  bytes for 4 GiB, 16 GiB and a high-memory value; the generated drop-in validates under systemd.

### Release + CI (HJ-24-4)
- **AC11** `app/VERSION` advances monotonically and `test/release-version.test.mjs` passes at the head.
- **AC12** The workflow produces a check run bound to the PR head SHA with full history. Repo-admin
  settings that cannot be verified are documented, not claimed.

### Shared gate (GOA-4, GOA-7)
- **AC13** `test/orch-contract-fixture.test.mjs` honours `PW_ORCHESTRATOR_CONTRACT_ROOT`.
- **AC14** A documented dependency-free offline target runs the no-Express subset on the exact head,
  uses a short isolated tmux socket root, and is deterministic across environments. Full
  `npm ci && npm test` remains the canonical gate.
- **AC15** tmux tests are hermetic against ambient `TMUX`, `TMUX_PANE`, `TMUX_TMPDIR`; host and
  container tests deliberately select matching socket roots; cleanup touches only isolated sockets;
  a paired ambient-set/ambient-unset run returns identical results.

### Container parity (GOA-2)
- **AC16** Container persistence/restore is either delivered with the env/state mount contract or its
  precise limitation is documented. No implied parity that does not exist.

### Product path (GOA-6)
- **AC17** The dashboard no longer mutates account-owned workspace Git config/credential artifacts as
  root; the work is routed through the established trusted non-root execution model, with a test
  asserting resulting ownership. No recursive chown of existing worktrees.

### Non-regression
- **AC18** One full canonical suite at the frozen head is green apart from environment-attributed
  failures explicitly named and explained. Host/container behaviour outside this scope is unchanged.
- **AC19** A new preserved round is appended to `DEVELOPMENT-COORDINATION.md`; prior rounds are not
  rewritten; no secrets/private URLs/inventory.
